## 1. Кратко о проекте

**Назначение.** Справочник организаций и специалистов, которые помогают детям
с расстройством аутистического спектра (РАС) в Казахстане. Родитель заходит,
подбирает подходящее место занятий по городу, типу места, специальности,
методу и возрасту ребёнка, открывает карточку с контактами и читает отзывы
других родителей.

Отличительная особенность: у каждого метода помощи проставлен **уровень
доказательности** - «Доказано», «Ограниченные данные» или «Без доказательств
при РАС». Метки видно и в карточке места занятий, и на отдельной странице с
описанием методов. Задача - помочь родителям отличить методы с исследованной
эффективностью от тех, у которых её нет.

**Статус разработки: рабочий прототип, в интернет не выложен.**

Что это значит на практике:

- Все основные сценарии живые: поиск с фильтрами, карточки, отправка отзыва,
  приём заявок от организаций и специалистов, модерация того и другого,
  админка с полным CRUD.
- База наполнена **только выдуманными тестовыми записями** - 12 штук, каждая
  подписана «(тестовая запись)» и помечена флагом `is_test`. Настоящих
  организаций в базе нет.
- Нет регистрации пользователей и деплоя. Оповещения администратора о новых
  заявках существуют только как пустая заготовка.
- Страница «Как получить помощь бесплатно» - заготовка с пустыми разделами.
- **Пароля администратора по умолчанию больше нет.** Пока не заданы
  `ADMIN_LOGIN` и `ADMIN_PASSWORD`, вход в админку отключён.
- Проект выложен на Render как тестовый стенд:
  https://erekshe-test.onrender.com. Сервис называется `erekshe-test`, создан
  руками через New - Web Service, а не из `render.yaml`, поэтому файл
  `render.yaml` сейчас ни на что не влияет и оставлен на будущее. Стенд
  настроен полностью: заданы `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `SECRET_KEY`,
  `IP_SALT`, `SHOW_TEST_BANNER=1` и `NOINDEX=1`, ветка `main`, Auto-Deploy
  включён. `TRUST_PROXY_HEADERS` не задан и не нужен: приложение определяет
  работу за балансировщиком по переменной `RENDER`, которую задаёт хостинг.
- Персональные данные посетителей обрабатываются по отдельным правилам:
  согласие записывается вместе с текстом, который человек видел; IP-адрес
  хранится только в виде хеша; контакты в списках админки замаскированы;
  есть удаление, обезличивание, сроки хранения и страница обращения.

## 2. Технологии

| Что | Чем реализовано |
|---|---|
| Язык | Python 3 (код использует синтаксис 3.10+: `X \| None`, `match`-независимый `:=`) |
| Веб-фреймворк | FastAPI 0.115.0 |
| Сервер | Uvicorn 0.30.6 (`uvicorn[standard]`) |
| Шаблоны | Jinja2 3.1.4 через `fastapi.templating.Jinja2Templates` |
| База данных | SQLite, файл `catalog.db` в корне проекта |
| ORM | **ORM нет.** Работа с базой идёт напрямую через модуль `sqlite3` из стандартной библиотеки, запросы написаны руками в `app/crud.py` |
| Сессии | `SessionMiddleware` из Starlette, подпись cookie через `itsdangerous` 2.2.0 |
| Формы | `python-multipart` 0.0.9 (нужен для multipart-форм с загрузкой файлов) |
| CSS | Один файл `app/static/style.css`, написан вручную, без фреймворков и сборки. Цвета и кегли заданы токенами в `:root` |
| Шрифты | Literata (заголовки) и Golos Text (текст), подключаются с Google Fonts в `base.html`. Обе гарнитуры с кириллицей; в запасном стеке Georgia и системный гротеск |
| JavaScript | **Отсутствует полностью.** В шаблонах нет ни одного тега `<script>`. Вся интерактивность - обычные HTML-формы и переходы по ссылкам |
| Хостинг / деплой | Render: `render.yaml` описывает веб-сервис, `runtime.txt` задаёт Python 3.11.9. Тестовый стенд работает по адресу https://erekshe-test.onrender.com (бесплатный тариф). Dockerfile, CI/CD и настроек nginx нет |
| Внешние сервисы | Только Google Fonts: страницы загружают шрифты с `fonts.googleapis.com` и `fonts.gstatic.com`. Аналитики, почты, SMS, платежей, карт, капчи и S3 нет. Остальные внешние адреса - обычные ссылки на `wa.me`, `instagram.com` и сайт организации |
| Тесты | **Нет.** Ни тестового фреймворка, ни файлов с тестами |

Всего в проекте около 4400 строк: 2039 строк Python, 1455 строк шаблонов,
874 строки CSS.

### Как запускается

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

При первом старте `catalog.db` создаётся автоматически и наполняется
справочником методов и тестовыми записями. Чтобы пересобрать данные с нуля,
файл базы удаляют и перезапускают приложение.

## 3. Страницы сайта

Все страницы отдают готовый HTML с сервера. Общий каркас - `base.html`:
шапка с логотипом слева, а справа - меню из двух пунктов («Каталог»,
«Методы помощи») и контурная кнопка «Разместиться в каталоге» рядом с ним. Пункт «Помощь бесплатно»
из меню убран, пока страница не наполнена текстом: сама страница и шаблон
на месте, но ссылок на неё в интерфейсе больше нет. Кнопки входа в
шапке нет: админка открывается только по прямому адресу `/admin`, а ссылки
«Админка» и «Выйти» появляются в шапке лишь после входа. В подвале дисклеймер
о том, что сайт носит информационный характер и не заменяет консультацию
врача, и две ссылки - «Разместиться в каталоге» и «Политика
конфиденциальности». Интерфейс на русском, вёрстка адаптивная под телефон.

**Оформление построено на одном правиле: цветом говорит только уровень
доказательности.** Сам интерфейс монохромный - графит, белый и прохладный
светлый фон; цветные на странице лишь три метки методов. Смысл в том, чтобы
родитель первым делом видел именно их. Заголовки набраны серифной Literata,
текст - гротеском Golos Text.

### `/` - каталог и поиск

Главная страница. Пользователь видит заголовок, короткое описание проекта,
блок фильтров «Подобрать помощь» и список найденных мест занятий карточками.

Перед фильтрами стоит блок **«Что значат метки у методов»** - расшифровка
трёх уровней доказательности с пояснением к каждому и оговоркой, что метка
говорит о состоянии исследований, а не о качестве работы конкретного
специалиста. Раньше эта расшифровка лежала в самом низу страницы, уже после
списка, который она объясняет.

Над списком выводится счётчик «Найдено: N». Если ничего не нашлось -
сообщение с предложением изменить фильтры.

Каждая карточка в списке показывает:

- фото или логотип; если изображения нет - цветная плашка с инициалами
  (цвет стабильно вычисляется из названия через CRC32);
- средняя оценка и число отзывов, либо «Нет отзывов»;
- название - ссылка на карточку;
- плашки методов, окрашенные по уровню доказательности;
- строку «Где заниматься: <тип места>, <специальность>» и метку «тестовая
  запись», если запись тестовая;
- возраст детей;
- строку «Есть гос. финансирование», если флаг проставлен;
- описание, обрезанное до 230 символов;
- сбоку - город и район, цена за занятие или «Бесплатно», кнопку действия
  и ссылку «Подробнее».

Кнопка действия выбирается по наличию данных: есть WhatsApp - «Написать в
WhatsApp», иначе есть телефон - «Позвонить», иначе - «Открыть карточку».

### `/providers/{id}` - карточка места занятий

Полная информация об одной записи:

- плашка с типом места, метка тестовой записи, оценка;
- логотип, название, специальность;
- описание целиком;
- кнопки «Позвонить» (`tel:`) и «Написать в WhatsApp» (`https://wa.me/<цифры>`);
- блок «Информация»: город, район, адрес, телефон, WhatsApp, сайт, Instagram,
  возраст детей, оплата, гос. финансирование («Есть» либо «Нет данных»).
  Пустые поля не выводятся;
- блок «Методы»: список методов с меткой уровня и пояснением для уровней
  «ограниченные данные» и «без доказательств»;
- блок «Отзывы»: только опубликованные, новые сверху, со звёздами и датой;
- форма «Оставить отзыв»: имя (до 80 символов), оценка 1–5 выпадающим списком,
  текст (до 2000 символов). Под формой предупреждение, что отзывы проходят
  модерацию и что не нужно указывать диагнозы и чужие персональные данные.

После отправки формы страница перезагружается с сообщением: «Отзыв отправлен
на модерацию», «С одного устройства можно оставить один отзыв о месте занятий
в сутки» или «Заполните имя, оценку и текст отзыва».

Если записи с таким `id` нет - ответ 404 с текстом «Запись не найдена».

### `/methods` - методы помощи

Справочник методов простым языком, сгруппированный по уровню доказательности
в порядке: сначала «Доказано», затем «Ограниченные данные», затем «Без
доказательств при РАС». У каждой группы своя метка и пояснение. Каждый метод -
карточка с названием, описанием и ссылкой «Найти, где занимаются этим
методом», которая ведёт на `/?method=<код>`.

Внизу оговорка, что уровень доказательности отражает состояние исследований,
а не качество работы конкретного специалиста.

### `/free-help` - как получить помощь бесплатно

**Ссылок на эту страницу в интерфейсе нет** - пункт убран из меню до тех пор,
пока страница не будет наполнена. Открыть её можно только по прямому адресу.

**Заглушка.** Страница выводит заголовок, пометку «Страница в подготовке -
текст будет добавлен позже» и пять пустых разделов: «Заключение ПМПК»,
«Государственный социальный заказ», «Портал социальных услуг и очередь»,
«Какие документы подготовить», «Куда обращаться в своём городе». В каждом
вместо содержания фраза «Текст будет добавлен».

### `/dlya-specialistov` - заявка на размещение

Страница для тех, кто хочет попасть в каталог. Заголовок «Разместите
информацию о себе в каталоге», подзаголовок про реабилитационные центры,
клиники, частных специалистов, детские сады и школы, блок «Как проходит
размещение» из трёх пронумерованных шагов (отправляете заявку → проверяем
информацию и можем запросить лицензию или диплом → публикуем карточку) и
пометка, что размещение бесплатное.

Дальше форма заявки. Первым делом переключатель «Вы заполняете анкету от
имени»: «Организации (центр, клиника, детский сад, школа)» или «Себя как
частного специалиста (работаю сам)». От выбора зависит, какие поля
показываются: организации - название и «Где заниматься», специалисту - ФИО
и специальность.
Переключение сделано **без JavaScript**, на CSS-селекторе `:has()`. Если
браузер его не поддерживает, правило не применяется и видны все поля сразу -
форма всё равно работает, потому что нужную ветку выбирает сервер.

Остальные поля общие: город, адрес, фото или логотип, методы работы
чекбоксами из справочника (с метками доказательности), возраст детей от и до,
стоимость занятия от и до или переключатель «Занятия бесплатные», сайт или
Instagram, контактное лицо, телефон, WhatsApp, почта, комментарий до 2000
символов и обязательный чекбокс согласия на обработку персональных данных
со ссылкой на `/privacy`.

Фото прикладывается прямо в форме - PNG, JPEG, WebP или GIF до 2 МБ. Рядом с
полем честно сказано, что при возврате формы с ошибками файл придётся выбрать
заново: подставить его обратно браузер не позволяет.

Если проверка не прошла, страница возвращается с красным блоком ошибок над
формой; всё введённое сохраняется, включая выбранный вариант «Кто вы» и
отмеченные методы.

### `/dlya-specialistov/sent` - заявка отправлена

Страница благодарности: «Спасибо! Мы проверим информацию и свяжемся с вами
в течение 2 рабочих дней», плюс короткое пояснение, что может понадобиться
лицензия или диплом.

### `/privacy` - политика конфиденциальности

Пометка вверху «Черновик, текст требует проверки юристом» осталась, рядом
указана версия и дата. Разделы: кто обрабатывает данные (оператор пока не
назван, и об этом сказано прямо), какие данные собираются - отдельно про
заявки, отзывы и обращения, зачем они нужны, на каком основании (согласие),
сколько хранятся, где хранятся, права субъекта и как обратиться. В разделе
про хранение прямо сказано, что требование хранить данные в Казахстане
сейчас не выполнено: стенд работает на сервере в Германии.

### `/privacy/request` - обращение по персональным данным

Форма «Отозвать согласие или удалить мои данные»: имя, телефон или почта для
ответа, суть обращения. Есть та же скрытая ловушка для ботов, что и в заявке,
и ограничение - не больше трёх обращений с одного устройства в час. На
странице указан срок ответа: 10 рабочих дней. Обращение попадает в блок
модерации админки.

### `/privacy/request/sent` - обращение отправлено

Короткая страница подтверждения со сроком ответа и ссылками назад.

### `/admin/requests` и `/admin/requests/{id}` - обращения в админке

Список с фильтром по статусу (Новое, В работе, Отвечено); контакт в списке
замаскирован, на странице обращения виден полностью. На странице можно
сменить статус, оставить заметку и удалить обращение.

### `/admin/reviews/{id}` - карточка отзыва

Текст отзыва целиком, место занятий, отметка о согласии с версией политики,
отпечаток адреса, кнопки модерации и блок «Персональные данные» с
обезличиванием и удалением. Если в отзыве встречаются слова о здоровье,
сверху выводится предупреждение.

### `/admin/login` - вход в админку

Форма с логином и паролем. При неверной паре - сообщение «Неверный логин или
пароль». Ссылки на эту страницу в публичном меню нет, но кнопка «Вход» в
правом углу шапки ведёт именно сюда.

### `/admin` - модерация и список мест занятий

Главная страница админки начинается с блока **«Требует проверки»** - это
единая точка входа для модерации. В нём две колонки: новые заявки и отзывы
на модерации, по пять последних в каждой. У заявки видно название, город,
тип заявителя, дату, контактное лицо и кнопку «Открыть». У отзыва - автор,
звёзды, дата, место занятий, начало текста и сразу кнопки «Одобрить» и
«Отклонить»: отзыв модерируется прямо отсюда, без перехода на другую
страницу. Заявки открываются на отдельной странице, потому что данных в них
намного больше. Если проверять нечего, вместо колонок выводится «Всё
проверено».

Ниже сводка: сколько всего записей и сколько методов в справочнике. Таблица со всеми записями: название
с логотипом и специальностью, где заниматься, город, оплата, оценка, кнопки
«Изменить» и «Удалить». Удаление спрашивает подтверждение и предупреждает, что
вместе с записью удалятся её отзывы.

### `/admin/providers/new` и `/admin/providers/{id}/edit` - форма записи

Одна и та же форма на создание и редактирование. Поля: где заниматься,
специальность, название (обязательно), город (обязательно), район, адрес,
телефон, WhatsApp, сайт, Instagram, возраст от и до, цена от и до, оплата,
переключатели «Есть гос. финансирование» и «Тестовая запись», загрузка фото
или логотипа, описание, чекбоксы методов с метками доказательности.

### `/admin/applications` - заявки на размещение

Список всех заявок, новые сверху. Фильтр по статусу плашками: «Все», «Новая»,
«В работе», «Одобрена», «Отклонена». В таблице дата, название или ФИО с типом
заявителя, город, контактное лицо с телефоном, статус цветной плашкой и, если
карточка уже создана, ссылка на неё.

### `/admin/applications/{id}` - карточка заявки

Все данные заявки: присланное фото рядом с названием (или пометка «Фото не
прислано»), тип заявителя, место занятий или специальность, город, адрес,
контакты, возраст детей, стоимость, дата согласия на обработку данных, IP
отправителя, дата обновления, методы плашками и комментарий заявителя.

Ниже блок обработки: кнопка «Создать карточку из заявки», выбор статуса,
поле «Заметка администратора» и кнопка удаления с подтверждением.

Кнопка «Создать карточку из заявки» открывает обычную форму новой записи,
заполненную данными заявки, с пояснением наверху. Присланное фото показывается
в форме и переносится в карточку; чтобы его заменить, администратор выбирает
в той же форме другой файл. Карточка появляется в
каталоге **только после нажатия «Сохранить»**; тогда же заявка получает
статус «Одобрена» и ссылку на созданную карточку, а администратор
возвращается на страницу заявки.

### `/admin/reviews` - модерация отзывов

Три списка: «На модерации», «Опубликованные», «Отклонённые». У каждого отзыва
автор, звёзды, дата, ссылка на место занятий и текст. У отзывов на модерации -
кнопки «Одобрить» и «Отклонить».

### `/admin/methods` и `/admin/methods/{id}/edit` - справочник методов

Таблица методов: порядок, код, название с обрезанным описанием, уровень
доказательности, кнопки «Изменить» и «Удалить». Под таблицей форма добавления
или редактирования метода.

## 4. Функции и их статус

### Поиск по названию - **готово**

Поле «Поиск по названию или ФИО». Ищет подстроку в названии записи, регистр не
важен. Чтобы регистр работал с кириллицей, в SQLite зарегистрирована
собственная функция `lower_ru`: встроенный `LOWER()` в SQLite понижает регистр
только у латиницы.

Поиск идёт **только по полю названия**. Описание, город и специальность
полнотекстово не ищутся.

### Фильтры - **готово**

Блок называется «Подобрать помощь». Пустое значение любого фильтра означает
«показать все результаты». Фильтры складываются по И: чем больше выбрано, тем
уже выборка.

| Фильтр | Значение по умолчанию | Значения |
|---|---|---|
| **Город** | Все города | Берутся из базы: только те города, которые реально встречаются у записей, по алфавиту. Сейчас это Актобе, Алматы, Астана, Караганда, Павлодар, Тараз, Усть-Каменогорск, Шымкент |
| **Где заниматься** | Все варианты | Реабилитационный центр, Медицинская клиника, Частный специалист, Коррекционный детский сад, Школа / инклюзивный класс, Государственная организация (ПМПК, КППК) |
| **Специальность** | Все специальности | Логопед, Дефектолог, АВА-терапевт, Нейропсихолог, Психолог, Эрготерапевт, Детский невролог, Детский психиатр |
| **Метод** | Все методы | Весь справочник методов, в порядке поля `sort_order`. Сейчас это 20 методов - те же, что на странице «Методы помощи» |
| **Возраст ребёнка** | Любой возраст | До 3 лет, 3–5 лет, 5–7 лет, 7–12 лет, Старше 12 лет |
| **Только доказательные методы** | выключен | Переключатель |

Как работают отдельные фильтры:

- **Город** - точное совпадение строки.
- **Где заниматься** - сравнение по коду в базе. Коды: `center`, `clinic`,
  `specialist`, `kindergarten`, `school`, `state`. В базе поле по-прежнему
  называется `provider_type` - переименован только интерфейс.
- **Специальность** - точное совпадение строки. Список фиксированный,
  задан в коде.
- **Метод** - запись подходит, если у неё проставлен метод с таким кодом.
  В выпадающем списке **только семь методов**, хотя в справочнике их двадцать.
  Остальные тринадцать (Логопедия, Эрготерапия, Обучение родителей,
  Дефектология, Арт-терапия, Иппотерапия, Адаптивная физкультура, Остеопатия,
  Краниосакральная терапия, Дельфинотерапия, Микрополяризация, Специальные
  диеты, БАДы) по-прежнему проставляются записям, показываются плашками в
  карточках и описаны на странице «Методы помощи», но отфильтровать по ним
  нельзя.
- **Возраст** - запись подходит, если её диапазон возрастов пересекается с
  выбранной группой. Границы групп: до 3 лет - это 0–2, дальше 3–5, 5–7, 7–12,
  старше 12 - это 13–18. Группы 3–5 и 5–7 намеренно пересекаются на пятёрке,
  как в подписях.
- **Только доказательные методы** - оставляет записи, у которых есть хотя бы
  один метод уровня «доказано» и нет ни одного метода уровня «без
  доказательств».

Сортировка результатов: сначала записи с оценкой, по убыванию оценки, потом
по названию. Записи без отзывов идут в конец.

Кнопка «Сбросить» - обычная ссылка на `/`.

### Карточки записей - **готово**

Описаны выше. Логотип загружается в админке; если его нет, рисуется плашка
с инициалами и стабильным цветом.

### Отзывы - **готово**

Любой посетитель может отправить отзыв без регистрации. Отзыв сохраняется со
статусом `pending` и на сайте не виден, пока администратор его не одобрит.

Проверки при отправке:

- имя, текст и оценка обязательны, оценка должна быть целым числом от 1 до 5;
- имя обрезается до 80 символов, текст - до 2000;
- **защита от спама:** с одного IP-адреса принимается не больше одного отзыва
  об одной записи в сутки. IP берёт функция `request_ip()` (см. раздел 7),
  при отсутствии пишется строка `unknown`.

Средняя оценка и число отзывов считаются на лету запросом по опубликованным
отзывам - отдельных полей в таблице записей для этого нет.

### Формы - **готово**

Все формы обычные HTML-овые, отправляются на сервер, после успеха -
редирект 303. Клиентской валидации сверх атрибутов `required` и `maxlength`
нет. Ошибки показываются либо сообщением на странице (отзывы), либо
параметром `?error=1` в адресе (админка).

### Заявки на размещение - **готово**

Организация или частный специалист заполняет форму на `/dlya-specialistov`,
заявка попадает в базу со статусом «Новая» и сразу видна администратору в
блоке «Требует проверки».

Проверки на сервере: тип заявителя выбран; название или ФИО заполнено (в
зависимости от выбранного варианта) и не длиннее 160 символов; город,
контактное лицо и телефон заполнены; телефон - казахстанский номер; WhatsApp,
если указан, тоже казахстанский номер; почта похожа на адрес; комментарий не
длиннее 2000 символов; согласие на обработку данных отмечено; возраст «от» не
больше «до»; стоимость «от» не больше «до». Методы, которых нет в справочнике,
отбрасываются молча.

Телефон нормализуется к виду `+7 701 234 56 78`. Принимаются записи с `+7`,
с `8` и без кода страны. Российские и прочие номера отсекаются: у всех
казахстанских номеров после кода страны идёт 6 или 7.

К заявке можно приложить фото или логотип. Тип файла определяется по
сигнатуре содержимого, а не по имени файла и не по заголовку от браузера;
принимаются PNG, JPEG, WebP и GIF до 2 МБ. Если файл не подошёл, заявка не
принимается и человек видит объяснение, а не молчаливую потерю фото.

Файл записывается на диск **только после того, как заявка прошла все
проверки**: сначала картинка читается в память и проверяется, и лишь при
успешной отправке сохраняется под случайным именем в `app/static/uploads/`.
Иначе каждая неудачная попытка оставляла бы на диске мусорный файл.

Защита от спама двойная. Скрытое поле-ловушка (honeypot) вынесено за левый
край экрана, помечено `aria-hidden` и исключено из обхода по Tab - человек
его не видит и не может заполнить. Если поле пришло непустым, заявка молча
отбрасывается, а отправитель видит обычную страницу благодарности. Плюс
ограничение: не больше трёх заявок с одного IP в час, при превышении
показывается понятное сообщение.

### Единый раздел модерации - **готово**

Блок «Требует проверки» на главной админки собирает в одном месте новые
заявки и отзывы на модерации. В меню админки пункт «На модерации (N)», где
N - сумма новых заявок и отзывов, ждущих проверки.

Счётчик считается функцией `moderation_counts()`, подключённой в шаблоны как
глобальная. Благодаря этому он одинаково работает на всех страницах админки -
раньше счётчик отзывов показывался только на `/admin`, а на остальных
страницах молча пропадал.

### Защита персональных данных - **готово**

Согласие записывается вместе с заявкой и отзывом: в таблице `consents`
лежит текст, который человек видел, цель, версия политики, дата, хеш адреса
и строка браузера. Без согласия ни заявка, ни отзыв не сохраняются.

IP-адрес в базу не попадает - только его хеш. В списках админки телефон и
почта показаны частично, на странице записи - полностью.

На странице заявки и на странице отзыва есть блок «Персональные данные»:
обезличить (контакты затираются, остаётся город, вид записи и даты) или
удалить насовсем. Оба действия спрашивают подтверждение, принимают
основание и пишут в журнал `data_actions`.

Сроки хранения проверяются при запуске: отклонённые заявки старше полугода
и отклонённые отзывы старше трёх месяцев обезличиваются сами.

### Обращения по персональным данным - **готово**

Страница `/privacy/request` принимает обращение (имя, контакт, суть),
ограничивает частоту тремя обращениями с устройства в час и кладёт
обращение в блок модерации. Срок ответа - 10 рабочих дней, он указан на
самой странице. В админке обращения живут отдельным списком со статусами
Новое, В работе, Отвечено. Связать обращение с конкретной заявкой или
отзывом автоматически код не умеет: администратор ищет запись сам.

### Предупреждение о сведениях о здоровье - **готово**

В анкете и в форме отзыва стоит заметное предупреждение не указывать
диагнозы, фамилии детей и другие данные о здоровье. Записи со
словами-маркерами помечаются в блоке модерации, в списках и на своих
страницах.

### Оповещения - **заглушка**

В `app/notifications.py` есть функция `notify_new_application(application)` с
описанием, но без реализации. Она вызывается после сохранения заявки внутри
`try/except`: сбой оповещения не мешает принять заявку. Отправку в Telegram
планируется сделать отдельным шагом.

### Регистрация и авторизация пользователей - **не начато**

Обычных пользователей в проекте нет вообще: ни регистрации, ни входа, ни
личного кабинета, ни таблицы пользователей. Отзывы оставляют анонимно, имя
автора - просто текст, который вписали в форму.

Есть только вход администратора - один на всех, см. раздел 7.

### Админка - **готово**

Полное управление содержимым:

- **Места занятий:** создание, редактирование, удаление, загрузка фото.
- **Отзывы:** одобрение и отклонение, три списка по статусам.
- **Справочник методов:** создание, редактирование, удаление, смена уровня
  доказательности и порядка вывода.

Загрузка изображений устроена аккуратно: тип файла определяется **по
сигнатуре содержимого**, а не по имени и не по заголовку от браузера.
Принимаются PNG, JPEG, GIF и WebP размером до 2 МБ, файл сохраняется под
случайным именем в `app/static/uploads/`. Если файл не подошёл, прежнее
изображение остаётся.

### Отправка уведомлений наружу - **не начато**

Ни почты, ни пуш-уведомлений, ни телеграма, ни SMS. Администратор узнаёт о
новом отзыве или заявке только когда сам зайдёт в админку и увидит счётчик.

### Страница «Помощь бесплатно» - **заглушка**

Разделы намечены, текста нет.

## 5. База данных

SQLite, файл `catalog.db` в корне проекта. Схема создаётся при старте
приложения из строки `SCHEMA` в `app/database.py`. Внешние ключи включаются

| `author_ip_hash` | TEXT | **Хеш** адреса отправителя, нужен для ограничения частоты. Сам адрес не хранится |
| `anonymized_at` | TEXT | Когда заявку обезличили; пусто, пока не обезличивали |
| `created_at`, `updated_at` | TEXT NOT NULL | Даты создания и изменения |

Два индекса: по паре «статус + дата» и по паре «хеш адреса + дата».

Методы заявки хранятся списком кодов в JSON, а не отдельной таблицей связей:
заявка - это ещё не карточка, и жёстко связывать её со справочником рано.
Коды, которых нет в справочнике, отбрасываются при разборе формы.

> **Персональные данные.** Заявка содержит имя контактного лица, телефон,
> WhatsApp и почту. Сохраняется только вместе с записью о согласии в таблице
> `consents`; отклонённая заявка обезличивается через полгода. Полный перечень
> полей и сроков - в `DATA_INVENTORY.md`.

### `consents` - согласия на обработку данных

| Поле | Тип | Смысл |
|---|---|---|
| `id` | INTEGER PK | |
| `subject_type` | TEXT NOT NULL | `application` или `review` |
| `record_id` | INTEGER NOT NULL | Номер заявки или отзыва |
| `purpose` | TEXT NOT NULL | Цель обработки одной строкой |
| `policy_version` | TEXT NOT NULL | Версия политики, действовавшая в тот момент |
| `consent_text` | TEXT NOT NULL | Текст, который человек видел на экране |
| `given_at` | TEXT NOT NULL | Когда дано |
| `ip_hash` | TEXT | Хеш адреса, с которого пришло согласие |
| `user_agent` | TEXT | Строка браузера, до 300 символов |
| `revoked_at` | TEXT | Когда согласие отозвали; пусто, пока действует |

Запись создаётся в той же транзакции, что и сама заявка или отзыв: данных
без согласия в базе быть не должно.

### `data_actions` - журнал действий с данными

| Поле | Тип | Смысл |
|---|---|---|
| `id` | INTEGER PK | |
| `action` | TEXT NOT NULL | `delete` или `anonymize` |
| `subject_type`, `record_id` | TEXT, INTEGER | Над какой записью |
| `reason` | TEXT | Основание, свободный текст, до 500 символов |
| `created_at` | TEXT NOT NULL | Когда |

Журнал переживает саму запись: после удаления в нём остаётся только её номер.

### `requests` - обращения по персональным данным

| Поле | Тип | Смысл |
|---|---|---|
| `id` | INTEGER PK | |
| `name` | TEXT NOT NULL | Как обращаться к человеку |
| `contact` | TEXT NOT NULL | Телефон или почта для ответа |
| `message` | TEXT NOT NULL | Суть обращения |
| `status` | TEXT NOT NULL, по умолчанию `new` | `new`, `in_progress`, `done` |
| `admin_note` | TEXT | Заметка администратора |
| `author_ip_hash` | TEXT | Хеш адреса, ограничение - три обращения в час |
| `created_at`, `updated_at` | TEXT NOT NULL | Даты |

### Связи

```
providers 1 ──< provider_methods >── 1 methods
providers 1 ──< reviews
providers 1 ──< applications        (необязательная: заявка может быть без карточки)
```

### Что происходит при запуске вместо миграций

Функция `init_db()` при каждом старте:

1. выполняет `CREATE TABLE IF NOT EXISTS` для всех таблиц;
2. переименовывает колонку `author_ip` в `author_ip_hash` у отзывов и заявок,
   добавляет колонку `anonymized_at` и один раз заменяет уже сохранённые
   открытые адреса их хешами;
3. создаёт индексы - после переименования, иначе индекс ссылался бы на
   колонку, которой на старой базе ещё нет;
4. добавляет колонку `logo_path` в `providers` и в `applications`, если её
   там нет (для баз, созданных раньше);
5. переносит записи со старым кодом `doctor` в `specialist`;
6. переименовывает устаревшие специальности: Невролог → Детский невролог,
   Психиатр → Детский психиатр, ABA-терапист → АВА-терапевт;
7. добавляет методы, появившиеся в справочнике позже создания базы.
   Названия уже существующих методов не трогает - их могли изменить в админке.

Все шаги идемпотентны: повторный запуск ничего не дублирует.

После этого вызывается `crud.cleanup_personal_data()`: отклонённые заявки
старше полугода и отклонённые отзывы старше трёх месяцев обезличиваются.
Отдельного планировщика в проекте нет, проверка идёт при каждом запуске.

Затем `seed_if_empty()` наполняет пустую базу: справочник методов, 12 тестовых
записей и 9 тестовых отзывов (7 опубликованных, 2 на модерации). Если записи
уже есть, функция ничего не делает.

### Как устроен код

- **`app/main.py`** - все маршруты, проверка доступа, разбор форм, загрузка
  изображений и вспомогательные фильтры для шаблонов: форматирование цены,

  слова-маркеры сведений о здоровье.
- **`app/crud.py`** - все SQL-запросы. Слой между маршрутами и базой.
  Параметры всегда передаются подстановкой, строки в запросы не склеиваются.

  функция `lower_ru` и проверки при запуске.
- **`app/reference.py`** - фиксированные справочники: типы мест, специальности,
  возрастные группы, уровни доказательности, виды оплаты, статусы заявок и
  обращений и стартовое наполнение справочника методов.
- **`app/seed.py`** - тестовые данные.
- **`app/notifications.py`** - заготовка оповещений администратора.

## 7. Роли и права доступа

Ролей **две**, и обе зашиты в коде.

**Посетитель (без входа).** Может смотреть каталог, фильтровать, открывать
карточки, читать опубликованные отзывы, отправлять свой отзыв на модерацию,
подавать заявку на размещение и обращение по своим персональным данным.
Больше ничего. Ни отзыв, ни заявка не
появляются на сайте, пока их не проверит администратор.

**Ограничение попыток входа.** Пять неверных попыток с одного IP-адреса
за 15 минут закрывают вход с этого адреса ещё на 15 минут. На странице входа
вместо формы выводится, через сколько минут можно повторить. Успешный вход
сбрасывает счётчик, старые неудачи забываются по истечении окна. Счётчик
живёт в памяти процесса: отдельной таблицы нет, при перезапуске всё
обнуляется, а при нескольких процессах каждый считает своё.

**Как определяется адрес посетителя.** Все счётчики - отзывы, заявки,
обращения и попытки входа - спрашивают адрес у одной функции `request_ip()`
в `app/main.py`. Обычно это адрес подключения (`request.client.host`). Если
приложение работает за балансировщиком, функция берёт первый адрес из
заголовка `X-Forwarded-For`. Признаётся это само: `detect_proxy()` смотрит
переменную `RENDER`, которую задаёт хостинг. `TRUST_PROXY_HEADERS`
переопределяет решение в обе стороны: `1` - доверять, `0` - не доверять.
Без балансировщика доверять заголовку нельзя: его подделывает любой
отправитель, и тогда счётчики обходятся в одну строчку.

**Что попадает в базу.** Не адрес, а его хеш: `sha256` от соли и адреса,
функция `personal_data.hash_ip()`. Соль берётся из переменной `IP_SALT`, а
без неё - из файла `.ip_salt` рядом с базой. Сравнить две записи между собой
по хешу можно, восстановить адрес - нет. В открытом виде адрес живёт только
в памяти процесса, в счётчике неудачных попыток входа.

**Что видит администратор.** В списках заявок, отзывов и обращений телефон
и почта показаны частично: `+7 70* *** ** 78`, `i***@mail.kz`. Полностью они
видны на странице конкретной записи, чтобы можно было связаться и
скопировать. Маскирование сделано фильтрами шаблонов `mask_phone`,
`mask_email` и `mask_contact`.

**Согласия.** Заявка и отзыв сохраняются только вместе с записью в таблице
`consents`: там лежит текст, который человек видел, цель, версия политики,
дата, хеш адреса и строка браузера. Версия политики - константа
`POLICY_VERSION` в `app/personal_data.py`, поднимается руками вместе с
текстом на `/privacy`.

**Удаление и обезличивание.** На странице заявки и на странице отзыва есть
блок «Персональные данные»: кнопка «Обезличить» затирает контакты и
оставляет обезличенную часть, кнопка «Удалить насовсем» стирает запись
вместе с согласием. Обе спрашивают подтверждение, у обеих есть поле
«Основание», и обе пишут в журнал `data_actions`. Присланное фото стирается
с диска, если на него не ссылается карточка каталога.

**Сроки хранения.** Функция `crud.cleanup_personal_data()` при каждом
запуске обезличивает отклонённые заявки старше полугода и отклонённые
отзывы старше трёх месяцев.

**Сведения о здоровье.** В анкете и в форме отзыва стоит предупреждение не
указывать диагнозы и данные детей. Записи, где встретились слова-маркеры
(аутизм, РАС, диагноз, ЗПР, эпилепсия, инвалидность, справка), помечаются в
блоке модерации и на своих страницах - чтобы модератор прочитал их
внимательнее. Список слов - `HEALTH_MARKERS` в `app/personal_data.py`.

**Администратор.** Один-единственный аккаунт. Логин и пароль берутся из
переменных окружения, значений по умолчанию нет: пока обе переменные пусты,
вход отключён и вместо формы выводится объяснение. Сравнение через
`secrets.compare_digest` - то есть защищено от атак по времени. Пароль **нигде
не хранится в виде хеша**: он сравнивается с переменной окружения напрямую.

После входа в сессию пишется единственный признак `admin = True`. Cookie
подписывается ключом `SECRET_KEY`. Проверка прав в каждом админском
обработчике - одна и та же строчка: есть признак в сессии или нет. Никакой
градации прав, отдельных модераторов или владельцев записей нет.

Ссылок на админку в публичном меню нет, кнопку «Вход» из шапки убрали:
админка открывается по прямому адресу `/admin`. Сама форма входа по-прежнему
доступна всем, кто знает адрес.

## 8. Переменные окружения

Значения нигде не приводятся - только названия и назначение.

| Переменная | Назначение | Если не задана |
|---|---|---|
| `ADMIN_LOGIN` | Логин для входа в админку | Вход в админку отключён |
| `PYTHON_VERSION` | Версия Python для Render; дублирует `runtime.txt` | Render берёт версию из `runtime.txt` |
| `ADMIN_PASSWORD` | Пароль для входа в админку | Вход в админку отключён |
| `DB_PATH` | Путь к файлу базы SQLite | База лежит в корне проекта |
| `UPLOAD_DIR` | Папка для загруженных фото | Папка `app/static/uploads` внутри проекта |
| `SHOW_TEST_BANNER` | Значение `1` включает полосу «Тестовая версия сайта» | Полосы нет |
| `NOINDEX` | Значение `1` закрывает сайт от поисковиков | Сайт открыт для индексации |
| `TRUST_PROXY_HEADERS` | Переопределяет доверие к заголовку `X-Forwarded-For`: `1` - доверять, `0` - не доверять | Решение принимается по переменной `RENDER` |
| `RENDER` | Задаётся хостингом Render. Её наличие включает доверие к `X-Forwarded-For` | Берётся адрес подключения |
| `IP_SALT` | Соль для хеширования адресов посетителей | Генерируется случайно и сохраняется в файл `.ip_salt` рядом с базой; файл в git не попадает |
| `PORT` | Порт, на котором слушает сервер | Задаётся при запуске uvicorn; на Render подставляется хостингом |
| `SECRET_KEY` | Ключ подписи cookie сессии администратора | Генерируется случайно и сохраняется в файл `.secret_key` рядом с базой; файл в git не попадает, а в логах при запуске появляется предупреждение |

Файл `.env` кодом не читается - библиотеки вроде `python-dotenv` не подключены.
Переменные нужно передавать окружением при запуске.

Пароля по умолчанию нет: без `ADMIN_LOGIN` и `ADMIN_PASSWORD` вход в админку
отключён.

На тестовом стенде заданы все нужные переменные: `ADMIN_LOGIN`,
`ADMIN_PASSWORD`, `SECRET_KEY`, `IP_SALT`, `SHOW_TEST_BANNER` и `NOINDEX`.
Поэтому предупреждение о незаданном `SECRET_KEY`, которое приложение пишет
в логи при запуске, на стенде не появляется, а ключ подписи сессии и соль
для хешей переживают перезапуск сервиса. Сама база при перезапуске всё
равно пересоздаётся: постоянного диска на бесплатном тарифе нет.

## 10. Известные проблемы, TODO и незавершённые места

Ниже только то, что видно в коде. Приоритет проставлен по влиянию на работу
сайта, а не по сложности исправления.

### Мешает выкладывать сайт в интернет

1. ~~Логин и пароль администратора по умолчанию - `admin` / `admin`.~~
   **Исправлено.** Значений по умолчанию нет: без заданных переменных вход
   отключён, а на странице входа выводится объяснение вместо формы.
2. **Пароль сравнивается с открытой строкой, хеширования нет.** Сравнение
   безопасное (`secrets.compare_digest`), но сам пароль лежит в переменной
   окружения в открытом виде.
3. **Нет защиты от CSRF.** Ни одна форма не содержит токена. Любая админская
   операция - создание, редактирование, удаление записи, одобрение отзыва,
   смена статуса и удаление заявки - выполняется обычным POST без проверки
   источника запроса. Форму заявки на размещение подключить к CSRF-защите
   тоже не удалось: подключать пока не к чему, механизма в проекте нет.
4. ~~Нет ограничения частоты входа в админку.~~ **Исправлено.** Пять неудач
   с адреса за 15 минут - и вход с него закрыт на 15 минут. Счётчик в памяти
   процесса, поэтому перезапуск сервиса снимает блокировки, а при нескольких
   процессах каждый считает своё.
5. ~~Деплой не настроен.~~ **Частично.** Стенд работает на Render по адресу
   https://erekshe-test.onrender.com; в репозитории есть `render.yaml`,
   `runtime.txt` и инструкция в README. Но на бесплатном тарифе Render нельзя
   подключить постоянный диск, поэтому база и загруженные фото пропадают при
   каждом перезапуске и создаются заново из тестовых данных. Для стенда с
   вымышленными записями это приемлемо, для настоящего сайта - нет: нужен
   платный тариф с диском либо внешняя база.
6. ~~Защита от спама держится на IP из прямого подключения.~~ **Исправлено.**
   За балансировщиком адрес берётся из заголовка `X-Forwarded-For`, и на
   Render это включается само - по переменной `RENDER`. Осталась оговорка:
   код доверяет первому адресу в заголовке и не проверяет, какой именно
   балансировщик его поставил. Это безопасно там, где к приложению нельзя
   обратиться напрямую, минуя балансировщик.

### Незаконченная функциональность

7. **Страница `/free-help` пустая.** Пять разделов без текста.
8. ~~Метод-фильтр показывает 7 методов из 20.~~ **Исправлено.** В фильтре
   весь справочник, в порядке `sort_order`; константы `FILTER_METHOD_CODES`
   больше нет. По четырём методам сейчас нет ни одной записи - фильтр по ним
   честно возвращает пустой список.
9. **Три вида мест занятий пока никем не заняты.** Среди тестовых записей нет
   ни одного коррекционного детского сада, школы и государственной
   организации - фильтр по ним вернёт пустой список.
10. **Уведомлений нет.** О новом отзыве администратор узнаёт только зайдя
    в админку.
11. **Нет пользователей и личных кабинетов.** Организация не может сама
    завести или отредактировать свою карточку - всё только через админку.
12. **Нет пагинации.** Каталог и админский список выводят все записи разом.
    На 12 тестовых записях это незаметно, на нескольких сотнях станет заметно.

### Мелкие недочёты в коде

13. ~~Счётчик отзывов в меню админки виден не на всех страницах.~~
    **Исправлено.** Счётчик считает функция `moderation_counts()`,
    подключённая в шаблоны как глобальная, поэтому «На модерации (N)»
    показывается на всех страницах админки.
14. **Две переменные передаются в шаблон каталога впустую.** Обработчик `/`
    кладёт в контекст `filters` и `specialties` (последняя - результат запроса
    `specialties_in_use` к базе), но шаблон ими не пользуется: список
    специальностей берётся из фиксированного справочника. Лишний запрос к базе
    на каждой загрузке главной.
15. **Справочник `TYPES_WITH_SPECIALTY` объявлен и передан в шаблоны, но нигде
    не используется.** Поле специальности в админской форме показывается
    всегда, независимо от выбранного типа места.
16. **`@app.on_event("startup")` устарел.** В текущих версиях FastAPI
    рекомендуется `lifespan`; при обновлении зависимостей это место
    выдаст предупреждение.
17. **Удалённые изображения остаются на диске.** Если в админке снять галочку
    логотипа или загрузить новый файл, ссылка в базе меняется, а старый файл
    в `app/static/uploads/` остаётся навсегда. То же и с заявками: удалили
    заявку с фото - файл остался. Уборки неиспользуемых файлов в проекте нет.
18. **Слово «провайдер» осталось в комментариях и именах в коде.** В интерфейсе
    его больше нет, но `provider_type`, `providers`, `provider_methods` и
    комментарии внутри Python-файлов используют прежний термин. Это сделано
    намеренно, чтобы не трогать схему базы.
19. **Уровни доказательности для четырёх методов проставлены без ссылок на
    источники.** Floortime (DIR) и Монтессори-терапия помечены как
    «ограниченные данные», логопедический массаж и нейрокоррекция - как «без
    доказательств при РАС». Источников в коде нет; формулировки стоит
    перепроверить со специалистом.

26. **Оповещения о заявках не отправляются.** `notify_new_application()` -
    пустая заготовка. Пока администратор не зайдёт в админку, он о новой
    заявке не узнает, а заявителю обещано, что с ним свяжутся в течение двух
    рабочих дней.
27. **Контакт для обращений по персональным данным не указан.** Страница
    `/privacy` описывает порядок удаления данных, но адреса или телефона, по
    которому обращаться, на ней нет - об этом там написано прямо.
28. **Политика конфиденциальности - черновик.** Текст написан своими словами
    и юристом не проверен, о чём сказано в пометке вверху страницы.
29. **Заявку нельзя отредактировать в админке.** Можно сменить статус,
    написать заметку, создать карточку или удалить заявку целиком; поправить
    опечатку в присланных данных нельзя - правки вносятся уже в созданной
    карточке.
30. **Переключение веток формы заявки зависит от `:has()`.** В браузере без
    поддержки этого селектора видны все поля сразу. Форма при этом работает:
    нужную ветку выбирает сервер по полю «Кто вы». Сломанного поведения нет,
    но выглядит менее аккуратно.
31. **Ограничение «три заявки в час» считается по всем заявкам с адреса**,
    включая уже отклонённые. Заявку, отброшенную ловушкой для ботов, в счёт
    не берём - она не сохраняется.

32. **Посетители без входа могут записывать файлы на диск.** Появилось вместе
    с фото в заявке. Ограничители: только PNG, JPEG, WebP и GIF по сигнатуре
    содержимого, не больше 2 МБ, не больше трёх заявок с адреса в час, имя
    файла случайное, запись только после успешной проверки формы. Но общего
    лимита на размер папки `app/static/uploads/` нет, и при выкладке сайта в
    интернет это стоит пересмотреть.
33. **Присланное фото нигде не проверяется на содержание.** Модератор видит
    его на странице заявки и решает сам; автоматических проверок нет.

34. **Шрифты грузятся с Google Fonts, и это задевает приватность.** При
    открытии любой страницы браузер посетителя обращается к
    `fonts.googleapis.com` и `fonts.gstatic.com`, то есть его IP-адрес уходит
    к Google. На сайте есть страница политики конфиденциальности, где про это
    ничего не сказано. Решается либо тем, что шрифты кладут рядом с сайтом
    и раздают со своего домена, либо честной оговоркой в политике. До выкладки
    в интернет это нужно закрыть.
35. **Если Google Fonts недоступен, страница берёт запасные шрифты** - Georgia
    для заголовков и системный гротеск для текста. Вёрстка не ломается, но
    выглядит иначе.
36. **Классы `.card-facts` и `.fact-accent` в CSS остались, а в шаблонах не
    используются** - мёртвый код от прежней вёрстки карточек.
37. **На страницу `/free-help` неоткуда перейти.** Маршрут и шаблон живы, но
    из меню пункт убран, и ни одна ссылка на неё не ведёт. Вернуть в меню
    нужно вместе с текстом страницы.
38. **Длинные тире в отзывах и заявках остаются как есть.** Тексты сайта
    набираются с обычным дефисом, и справочник методов приводится к нему
    миграцией при запуске, но присланное людьми не переписывается: это чужой
    текст.

### Отдельно про данные

24а. **Оператор персональных данных не назван.** Ни в коде, ни в политике
    нет юридического лица, которое отвечает за базу. До запуска настоящего
    сайта это нужно заполнить на `/privacy` и в `DATA_INVENTORY.md`.
24б. **Данные лежат не в Казахстане.** Стенд работает на Render в регионе
    Frankfurt, а закон требует хранить персональные данные граждан
    Казахстана на серверах в Казахстане. В политике это сказано прямо.
24в. **Обращения по данным обрабатываются руками.** Страница
    `/privacy/request` только принимает обращение и кладёт его в блок
    модерации; связать обращение с конкретной заявкой или отзывом
    автоматически код не умеет - администратор ищет запись сам.
24г. **Сроки хранения проверяются только при запуске.** Планировщика нет: на
    сервисе, который месяцами не перезапускается, просроченные записи
    останутся необезличенными.
25. **Вся база - выдумка.** Все 12 записей помечены «(тестовая запись)» и
    флагом `is_test`, телефоны вида `+7 700 000 00 0X`, адреса вроде «ул.
    Примерная, 12». Настоящих организаций в каталоге нет. Откуда будут браться
    реальные данные и кто их будет проверять - **не удалось определить**.
