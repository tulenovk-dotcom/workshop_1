# Каталог помощи детям с РАС в Казахстане

Веб-приложение со справочником реабилитационных центров, клиник, частных
специалистов, коррекционных детских садов и школ. У каждого метода указан
уровень доказательности. Отзывы и заявки на размещение публикуются после
модерации.

Стек: Python + FastAPI, SQLite, Jinja2, чистый CSS (без фреймворков).
Шрифты — Literata и Golos Text, подключаются с Google Fonts.
Интерфейс на русском языке, адаптивный под телефон.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

Открыть: http://127.0.0.1:8000

Вход в админку — http://127.0.0.1:8000/admin, логин `admin`, пароль `admin`.
Ссылки на админку в публичном меню нет.

База `catalog.db` создаётся автоматически при первом запуске и наполняется
справочником методов и 12 тестовыми провайдерами (помечены как тестовые).
Чтобы пересобрать данные заново, удалите файл `catalog.db` и перезапустите
приложение.

## Переменные окружения

| Переменная       | По умолчанию | Назначение                        |
|------------------|--------------|-----------------------------------|
| `ADMIN_LOGIN`    | не задан     | логин для входа в `/admin`        |
| `ADMIN_PASSWORD` | не задан     | пароль для входа в `/admin`       |
| `SECRET_KEY`     | файл `.secret_key` рядом с базой | подпись cookie сессии админки |
| `DB_PATH`        | `catalog.db` рядом с проектом | путь к файлу базы |
| `UPLOAD_DIR`     | `app/static/uploads` | папка для загруженных фото |
| `SHOW_TEST_BANNER` | не задана  | `1` включает полосу «Тестовая версия сайта» |
| `NOINDEX`        | не задана    | `1` закрывает сайт от поисковиков |
| `TRUST_PROXY_HEADERS` | определяется по `RENDER` | `1` берёт адрес посетителя из `X-Forwarded-For`, `0` запрещает |
| `IP_SALT`        | файл `.ip_salt` рядом с базой | соль для хеширования адресов посетителей |
| `RENDER`         | задаётся хостингом | её наличие включает доверие к `X-Forwarded-For` |

**Пароля по умолчанию у админки нет.** Пока `ADMIN_LOGIN` и `ADMIN_PASSWORD`
не заданы, вход отключён: на `/admin/login` вместо формы выводится объяснение.
Для локальной работы задайте их при запуске:

```bash
ADMIN_LOGIN=admin ADMIN_PASSWORD=admin \
  .venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

Если `SECRET_KEY` не задан, при первом запуске рядом с проектом создаётся файл
`.secret_key` (в git не попадает). Благодаря этому вход в админку не сбрасывается
при автоперезагрузке `uvicorn --reload`.

Без фиксированного `SECRET_KEY` сессия администратора сбрасывается при каждом
перезапуске приложения.

## Публикация на Render

**Тестовый стенд:** https://erekshe-test.onrender.com - на нём работает это же
приложение из ветки `main`. Админка там по адресу `/admin`.

Как стенд устроен на самом деле:

| Что | Как настроено |
|---|---|
| Имя сервиса | `erekshe-test` |
| Как создан | руками через **New → Web Service**, не из `render.yaml` |
| Ветка | `main`, Auto-Deploy включён: коммит в `main` выкатывается сам |
| Регион и тариф | Frankfurt, Free |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |

Поскольку сервис создан руками, **`render.yaml` на него не влияет**: все
переменные задаются в панели Render. Файл оставлен для будущего Blueprint,
если сервис когда-нибудь будут пересоздавать.

Что нужно помнить про бесплатный тариф: без посетителей сервис засыпает, и
первое открытие после сна занимает около минуты; база и загруженные фото
при перезапуске пропадают и создаются заново из тестовых данных.

### Какие переменные окружения заданы на стенде

`ADMIN_LOGIN`, `ADMIN_PASSWORD`, `SHOW_TEST_BANNER=1`, `NOINDEX=1`.

### Что стоит добавить

| Переменная | Значение | Что изменится |
|------------|----------|---------------|
| `SECRET_KEY` | длинная случайная строка | администратор перестанет вылетать из админки при каждом перезапуске сервиса |
| `IP_SALT` | длинная случайная строка | ограничения «один отзыв в сутки» и «три заявки в час» перестанут сбрасываться при перезапуске |

Без этих переменных сайт работает: ключ и соль создаются сами в файлах
рядом с базой. Но на бесплатном тарифе диск не сохраняется, поэтому при
каждом перезапуске файлы пропадают вместе с базой. В логах при запуске
видно предупреждение про `SECRET_KEY`.

`TRUST_PROXY_HEADERS` на Render задавать **не нужно**: приложение само
понимает, что стоит за балансировщиком, по переменной `RENDER`, которую
задаёт хостинг. Без этого сайт видел бы один и тот же адрес у всех
посетителей, и пять чужих неудачных попыток входа закрыли бы админку для
всех сразу. Переменная нужна только чтобы переопределить поведение руками:
`1` - доверять заголовку, `0` - не доверять.

Пока `ADMIN_LOGIN` и `ADMIN_PASSWORD` не заданы, сайт работает, но на
странице входа вместо формы выводится объяснение.

### Если сервис придётся создавать заново

1. https://dashboard.render.com, вход через GitHub.
2. **New → Blueprint**, репозиторий `workshop_1`, ветка `main` - Render
   прочитает `render.yaml` и покажет, какой сервис будет создан. Либо
   **New → Web Service** и те же команды сборки и запуска, что в таблице выше.
3. **Apply**. Первая сборка занимает несколько минут.
4. Задать `ADMIN_LOGIN` и `ADMIN_PASSWORD` в **Environment**.

### Где смотреть логи

**Сервис → Logs** - и вывод сборки, и то, что приложение пишет во время
работы; ошибки запуска видно там же. Вкладка **Events** рядом показывает
историю деплоев: когда запускался, чем закончился.

### Что нужно знать про бесплатный тариф

- **Постоянный диск на нём недоступен** - диски есть только на платных типах
  инстансов. База и загруженные фото живут до перезапуска, потом создаются
  заново из тестовых данных. Для стенда с вымышленными записями это обычно
  и нужно; если нет - в `render.yaml` поменяйте `plan` на `starter`,
  раскомментируйте блок `disk` и переменные `DB_PATH` и `UPLOAD_DIR`.
- Сервис засыпает после 15 минут без запросов. Первый запрос после сна
  открывается около минуты - это нормально, а не поломка.
- Заявки и отзывы, оставленные на стенде, пропадут при следующем деплое.

## Страницы

| Адрес            | Назначение                                                     |
|------------------|----------------------------------------------------------------|
| `/`              | поиск и фильтры «Подобрать помощь»: город, где заниматься, специальность, метод, возраст, только доказательные методы |
| `/providers/{id}`| карточка места занятий, методы с метками доказательности, отзывы, форма отзыва, кнопки «Позвонить» и «Написать в WhatsApp» |
| `/methods`       | описание методов простым языком с метками доказательности      |
| `/free-help`     | страница-заготовка «Как получить помощь бесплатно»             |
| `/dlya-specialistov` | как проходит размещение и форма заявки для организаций и частных специалистов |
| `/privacy`       | политика конфиденциальности (черновик, нужна проверка юристом) |
| `/admin`         | блок «Требует проверки», записи каталога (CRUD), справочник методов |
| `/admin/applications` | заявки на размещение: список с фильтром по статусу, карточка заявки, создание записи из заявки |
| `/admin/reviews` | модерация отзывов                                              |

## Модель данных

- `providers` — тип, название или ФИО, специальность, город, район, адрес,
  телефон, WhatsApp, сайт, Instagram, возраст детей, цена за занятие,
  бесплатно/платно, гос. финансирование, описание, метка тестовой записи.
  Средняя оценка и число отзывов считаются автоматически по опубликованным
  отзывам.
- `methods` — код, название, описание, уровень доказательности
  (`proven` — доказано, `limited` — ограниченные данные,
  `none` — без доказательств при РАС), порядок вывода.
- `provider_methods` — связь провайдеров и методов.
- `reviews` — имя автора, оценка 1–5, текст, дата, статус
  (на модерации / опубликован / отклонён), IP автора.
- `applications` — заявки на размещение: тип заявителя (организация или
  частный специалист), название или ФИО, место занятий или специальность,
  город, адрес, методы списком кодов, возраст детей, стоимость, сайт или
  Instagram, фото или логотип, контактное лицо, телефон, WhatsApp, почта,
  комментарий,
  статус (новая / в работе / одобрена / отклонена), заметка администратора,
  ссылка на созданную карточку, время согласия на обработку данных,
  IP автора, даты создания и изменения.

Защита от спама: с одного IP принимается не больше одного отзыва о месте
занятий в сутки и не больше трёх заявок в час. В форме заявки есть скрытое
поле-ловушка: если оно заполнено, заявка молча отбрасывается.

Телефоны в заявке приводятся к виду `+7 701 234 56 78`; принимаются только
казахстанские номера.

К заявке можно приложить фото или логотип: PNG, JPEG, WebP или GIF до 2 МБ.
Тип файла определяется по сигнатуре содержимого, а не по имени и заголовку
от браузера. Файл записывается в `app/static/uploads/` только после того,
как заявка прошла все проверки, и переносится в карточку, когда
администратор создаёт её из заявки.

## Оповещения

`app/notifications.py` содержит заготовку `notify_new_application()` — она
вызывается после сохранения заявки. Реализации пока нет; ошибка внутри неё
не мешает принять заявку.
